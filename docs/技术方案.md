# CRM 技术方案

CRM 管理线索、客户、联系人、商机、活动、服务工单和知识库。销售阶段和工单升级的规则在本系统。IR 只读快照并请求“前进一步”或“升级一次”。

## 1. 运行位置

| 场景 | 后端 |
| --- | --- |
| 单机 | `8080` |
| 与控制塔同机 | `8091` |

Open IR 请求头 `X-Api-Key`，种子键 `crm-open-key`。

## 2. 主链路

```text
线索 → 客户 / 联系人 / 商机
商机按阶段前进
工单按优先级升级，并受 SLA 约束
```

商机下一阶段和工单下一优先级都由本系统计算。调用方只给当前单据，不传目标阶段。

## 3. 控制塔读

`GET /api/open/ir/snapshots`：

| dataType | 业务键 |
| --- | --- |
| `OPPORTUNITY` | 商机 id |
| `CASE` | 工单号 `caseNo` |

## 4. 控制塔写

必须带 API Key。控制塔登录模式不调用本系统，因为登录口的改阶段要求调用方自己知道下一阶段。

| 指令 | 专用口 | 作用 |
| --- | --- | --- |
| `CRM_ADVANCE_STAGE` | `POST /api/open/ir/advance-stage` | 按商机 id 进入下一阶段 |
| `CRM_ESCALATE_CASE` | `/escalate-case` | 按工单号或 id 升级 |

统一口是 `POST /api/open/ir/actions`。`opportunityId`、`caseNo` 可代替 `targetKey`。非空幂等键去重，所以同一次升级不会连跳两级。

## 5. 边界

推进和升级各走一步。控制塔不创建线索、不改客户主数据、不关单。重复请求应看到同一阶段或同一优先级，而不是再次升级。
