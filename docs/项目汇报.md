# 智华 CRM 项目汇报

> 对标 Salesforce Sales Cloud / Service Cloud 的销售与客户服务一体化平台
> 技术栈：JDK 8 · Spring Boot 2.7 · Vue 3 · Element Plus

---

## 一、项目背景与目标

销售与服务团队长期面临线索散落、商机进展不透明、报价审批靠口头、工单响应无 SLA、管理层看不到数据等问题。项目目标是参考行业标杆 Salesforce 的对象模型与流程设计，在自有技术栈上搭建一套覆盖 **线索 → 商机 → 报价 → 审批 → 合同 → 回款** 的销售全流程和 **工单 → SLA → 满意度 → 知识库** 的服务全流程的 CRM 平台，并具备企业级的权限、审计、通知与报表能力。

**设计原则**

- 对象模型对齐 Salesforce（Lead / Account / Contact / Opportunity / Quote / Case / Knowledge / Campaign / Contract），团队上手成本低；
- 轻量部署：默认 H2 文件库零依赖启动，一条命令切换 MySQL；
- 前后端分离、接口全部 RESTful 并附 Swagger 文档；
- 每期功能交付均附单元测试 + 全链路冒烟脚本 + 浏览器端到端验证。

## 二、整体架构

```
┌──────────────────────────────────────────────────────────┐
│  前端  Vue 3 + Vite + Element Plus + ECharts (5173)        │
│  登录 / 仪表盘 / 销售 / 服务 / 审批 / 报表 / 系统管理       │
└───────────────────────────┬──────────────────────────────┘
                            │ /api  (JWT Bearer)
┌───────────────────────────▼──────────────────────────────┐
│  后端  Spring Boot 2.7 (8080)                             │
│  Controller → Service → Spring Data JPA (Specification)   │
│  Security: JWT 认证 + @PreAuthorize 角色控制 + 数据范围过滤 │
│  横切: 审计过滤器 / 字段变更历史 / 通知 & 渠道分发 / 定时任务 │
└───────────────────────────┬──────────────────────────────┘
                            │
      ┌─────────────────────┴─────────────────┐
      │  H2 (默认，文件库)  或  MySQL 8 (profile)  │
      └───────────────────────────────────────┘
      外部：SMTP 邮件、Webhook (HMAC-SHA256 签名)
```

| 层 | 技术 |
|---|---|
| 后端 | JDK 8、Spring Boot 2.7.18、Spring Data JPA、Spring Security + JWT、springdoc-openapi、Spring Mail |
| 数据库 | H2（默认）/ MySQL 8（`mysql` profile） |
| 前端 | Vue 3、Vue Router 4、Vite、Element Plus、ECharts、Axios |
| 质量 | JUnit 5 集成测试 36 个、`scripts/smoke.sh` 全链路冒烟、浏览器端到端测试 |

**规模概览**：后端 Java 195 个文件 / 约 1.07 万行，38 个 JPA 实体，28 个 Controller / 176 个 REST 接口；前端 Vue/JS 约 5,300 行；累计 34 次提交、9 个已合并 PR。

### 五期 · 数据权限、可配置仪表盘与消息渠道

- **细粒度数据权限**：按「角色 × 对象」配置 全部 / 团队 / 本人 三种数据范围，列表查询与单条读写统一过滤；支持将单条记录共享给指定用户（只读 / 可编辑）

## 四、核心流程设计

**1. 线索到回款（Lead-to-Cash）**

```
线索 → 转化 → 客户/联系人/商机 → 商机产品 → 报价单
   → 折扣触发审批规则 → 多级审批 → 报价接受 → 合同 → 回款计划 → 回款记录
```

**2. 服务工单闭环**

```
工单创建 → 自动分派规则匹配负责人 → SLA 计时
   → 超时定时升级 + 通知 → 处理/评论 → 关闭 → 满意度调查 → 沉淀知识库
```

**3. 权限模型（三层）**

| 层级 | 机制 | 说明 |
|---|---|---|
| 功能权限 | `@PreAuthorize` + 前端菜单权限表 | 角色能进哪些模块、能否写 |
| 数据范围 | `DataScopeService` 注入 JPA `Specification` | 全部 / 团队 / 本人 |
| 记录共享 | `RecordShare` | 跨团队按需共享单条记录 |

**4. 可观测性**

- 审计过滤器挂在 JWT 认证之后，记录写请求；审计失败不阻断业务
- 字段级变更历史记录商机、工单等关键对象的每次修改
- 通知 → 渠道分发链路异步执行，投递结果可追溯

## 七、部署与使用

```bash
# 后端（默认 H2，无需额外依赖）
cd backend && mvn spring-boot:run            # http://localhost:8080
# 切换 MySQL
mvn spring-boot:run -Dspring-boot.run.profiles=mysql

# 前端
cd frontend && npm install && npm run dev    # http://localhost:5173
```

- Swagger：`http://localhost:8080/swagger-ui.html`
- 默认账号：`admin/admin123`（管理员）、`manager/123456`（销售经理）、`sales/123456`（销售代表）、`service/123456`（客服）
- 邮件渠道：在 `application.yml` 中开启 `crm.mail.enabled=true` 并配置 `spring.mail.*`
